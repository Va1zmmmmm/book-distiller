# 真实模型小样本记录（2026-10-09）

测试使用仓库内的新编材料，不是商业书籍或真实用户阅读数据。实际调用了 cmdc 的 `deepseek/deepseek-v4-flash` 和 DeepSeek 官方接口的 `deepseek-v4-flash`；官方响应 model 字段为 `deepseek-flash`。这只是本次特定通道/模型的实测，不承诺其他接口或今后的持续可用性。

## 已观察到的结果

- 小说卡：保留了读者尚未分清等待与习惯的状态，没有转成操作方法。可以留空，也可以保留没有“怎么用”的具体意象或未解问题。
- 方法卡：保留了材料中的三步，不声称使用后对方一定满意。cmdc 与官方接口均生成过通过结构/出处校验的候选。
- 三章备料：官方接口逐章生成摘要/导航，引文字面回源通过。原文保留，第一章会话包不含后章标题、内容和分析。
- 三轮脚本化陪读：先不提问、说不知道后停止追问、对后文猜想不确认；本次模型遵守了这些要求，所登记引文对应已读原文。

这不是陌生读者用户测试，也不能证明所有书的理解质量、长书稳定性或绝不剧透。卡片仍有重复或偏长的表达，导航也可能把普通时间/物件拆成不必要的概念；陪读个别空间或动作解释比原文更确定。内容仍应逐条看，AI解释和读者认领不能合并。

## 失败也属于结果

初次 cmdc 使用 Python 默认请求标识时返回403；改用明确的 `BookDistiller/版本` 标识后同一材料得到200，已写入适配层。具体服务端拦截原因未得到确认。

旧提示词包含两套不完全一致的输出结构，真实响应漏来源字段、混用 `〔h1〕` 与 `〔划线1〕`，被拒绝。现已统一JSON契约，并明确一维/二维来源数组及概括结束标记。补清格式的过程中也出现过来源数组层级不合规和概括标记后多句号的响应，未改写成“成功”。

通过的是修改后重新生成的候选，没有手工给失败响应补出处，也没有放松引文匹配。模型仍可能输出坏JSON、错误层级或错误解释；当前程序不会自动费用重试，不能把这份记录当成首次生成成功率报告。

如果响应被拒绝，可在新输出目录、显式 `--cache-dir` 下请求：缓存保存外部候选，命中后仍重验。缓存可能包含隐私，放在本地受控目录。检查字段与原材料，不为跑通而放松验证，也不直接认领未经自己阅读的观点。
